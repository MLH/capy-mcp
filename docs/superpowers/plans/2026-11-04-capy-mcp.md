# Capy MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Expose 102 named Capy API tools to Hermes and other MCP clients over private Workers HTTP or local STDIO.

**Architecture:** Generate a pinned operation catalog and standalone JSON Schema validators at build time. A shared MCP server uses that catalog and a bounded Capy HTTP client; thin transport entry points provide authentication and lifecycle management.

**Tech Stack:** TypeScript ESM, Node.js >=22, official MCP SDK v2 (`@modelcontextprotocol/server` 2.4.0 and matching core/client packages), Ajv 8 standalone generation, esbuild, npm with a lockfile, Wrangler 4, Vitest 4.1 with a compatible Cloudflare Workers pool. Pin installed compatible versions. Do not use Vitest 5 with the current Workers pool, whose peer range is ^4.1.0.

**Spec:** `docs/superpowers/specs/2026-11-04-capy-mcp-design.md`

## Global Constraints

- Include the 102 non-legacy JSON operations; exclude only `tasks.list`, `tasks.get`, `tasks.messages`, `streams.thread`, `streams.subagent`, and `streams.task` from the pinned 108-operation contract.
- Use the fixed HTTPS Capy API origin `https://api.capy.ai`.
- Configuration names: `CAPY_API_KEY`, `CAPY_TOOL_GROUPS`, `MCP_AUTH_TOKEN`, `MCP_ALLOWED_ORIGINS`.
- Named tools use `capy_` plus snake-cased operation IDs and `path`, `query`, `body` argument objects.
- No OAuth server, credential store, automatic mutation retries, automatic pagination, deployment, package publication, license selection, payload logging, or continuous SSE tools.
- No runtime schema compilation/eval on Workers: generate standalone validators ahead of time, and retain equivalent advertised JSON schemas.
- Use a 30-second upstream deadline, a 1 MiB upstream response limit, and a 1 MiB MCP POST body limit. Report limits explicitly; never silently truncate.
- Work in this thread's isolated cloud checkout. Keep the implementation on the existing PR branch unless that PR has closed; do not merge without an explicit merge request.

## Review Focus

1. Path values `.` and `..` must not let URL normalization switch API routes; empty values and slash-bearing IDs must not inject segments (Task 2).
2. Unknown groups, empty group strings, and direct calls to disabled tools must fail closed rather than fall back to all tools (Tasks 1 and 2).
3. Upstream exceptions or JSON errors that echo credentials or request bodies must not leak through MCP errors or logs (Task 2).
4. A slow response body, missing content length, or concurrent requests in one Worker must respect limits without sharing credentials or state (Tasks 2 and 3).
5. Future OpenAPI changes must not silently lose references, unsupported serialization, schema keywords, or operations (Task 1).

- `src/catalog.ts`: catalog types, configuration parsing, enabled-operation selection.

- `tests/catalog.test.ts`, `tests/client.test.ts`, `tests/server.test.ts`, `tests/stdio.test.ts`, `tests/worker.test.ts`: corresponding observable behavior.
- `package.json`, `package-lock.json`, `tsconfig.json`, `vitest.config.ts`, `vitest.workers.config.ts`, `wrangler.jsonc`, `.gitignore`, `.github/workflows/ci.yml`: package/toolchain/runtime checks.

## Task 1: Generated, validated API catalog

**Interfaces:** `buildCatalog(document: OpenApiDocument): Operation[]`; `Operation` has `name`, `operationId`, `group`, `method`, `route`, `description`, `inputSchema`, and `annotations`. Runtime `selectOperations(groups?: string): Operation[]` returns selected operations or throws a sanitized configuration error. Generated validators expose a name-keyed map of boolean validation functions; validation performs no coercion, defaults, removal of properties, or runtime code generation.

- [ ] Create package/test configuration and lock compatible tooling; copy the previously fetched contract into `api/openapi.json` and record its digest/date/source.
- [ ] Write failing catalog tests: exactly 102 tools plus six accounted exclusions, deterministic snake-case names, collision rejection, required path/body versus optional query objects, nested refs/unions/enums/additional properties, unknown references and unsupported parameter serialization rejected, and fail-closed group selection.
- [ ] Run `npx vitest run tests/catalog.test.ts`; verify failures identify the missing catalog behavior before implementation.
- [ ] Implement `buildCatalog` and generation from the snapshot. Preserve reachable definitions in self-contained tool JSON schemas; compile these exact schemas with Ajv's draft-appropriate compiler and standalone output. Validate every schema against supported JSON Schema semantics rather than approximating it with Zod. Enrich Captain, issue, and message descriptions. Generate read-only GET annotations and conservative mutation annotations.
- [ ] Implement `npm run generate`, `npm run generate:check`, and `npm run api:refresh`. Check mode compares artifacts and source digest without modifying files; refresh is an explicit network operation. Runtime never loads the remote contract.
- [ ] Run the catalog suite and generation check; ensure a deliberately altered generated artifact is detected, then restore by generation. Commit the passing task.

## Task 2: Shared Capy client and MCP tools

The injectable fetch is only an internal testing seam, never MCP input.

- [ ] Write failing client tests for route and query encoding, preserved body/null/false/zero values, header separation, dot-segment rejection, no redirects, preserved pagination, structured API errors, 429 retry information, invalid JSON, no automatic retry, cancellation, stalled headers/body, oversized chunked responses, and redaction of echoed secrets/request data.
- [ ] Write failing in-memory MCP client/server tests for initialization/listing, Captain creation and messaging, issue creation/update/listing, required request IDs, unknown or disabled tools, and invalid nested arguments causing zero upstream requests.
- [ ] Run `npx vitest run tests/client.test.ts tests/server.test.ts`; verify these expectations fail before implementing the behavior.
- [ ] Implement fixed-origin request construction and bounded response reads with one combined cancellation/deadline signal. Disallow redirects, reject unsafe dot segments, and use explicit response errors rather than truncation. Expose only sanitized error status/tag/retry metadata, never raw upstream prose or exception text.
- [ ] Implement low-level SDK `Server` handlers using method strings `tools/list` and `tools/call`, returning the same schemas used by generated validators. Return successful upstream objects as structured content and JSON text; wrap non-object JSON as `{ result: value }` for structured compatibility. Invalid/unknown tool requests use protocol errors; upstream failures use `isError: true` tool results. Propagate request cancellation.
- [ ] Run all existing tests and `npm run typecheck`; commit only after they pass.

**Interfaces:** `src/stdio.ts` executes the shared factory with process configuration and `StdioServerTransport` from `@modelcontextprotocol/server/stdio`. `src/worker.ts` exports a standard Worker `fetch(request: Request, env: Env): Promise<Response>`. Generate Worker bindings/types from Wrangler instead of duplicating platform interfaces. Both entry points use the Task 2 factory unchanged.

- [ ] Write failing child-process tests using the official MCP client: production CLI initializes, lists the configured tools, closes cleanly, and never contaminates stdout. Missing/invalid configuration exits nonzero without disclosing credentials.
- [ ] Write failing Worker-runtime tests for authenticated initialization, listing and representative tool execution, 401 with no upstream work, absent/equal credentials failing closed, default Origin denial, exact allowlist acceptance, denied Origins, no permissive CORS, unknown routes, protocol-appropriate methods, oversized bodies, and parallel request isolation using different environment credentials.
- [ ] Run the STDIO and Worker tests before their entry points exist; verify expected failures.
- [ ] Implement STDIO with sanitized startup errors and graceful shutdown. Bundle `dist/stdio.js` with a Node shebang, expose it as the `capy-mcp` executable, and make the production artifact the child-process test target.
- [ ] Implement `/mcp` using `WebStandardStreamableHTTPServerTransport`, request-local server/transport instances, no session IDs, and JSON responses. Authenticate before constructing the server or contacting upstream. Compare a hash of the supplied token against the configured secret using Web Crypto verification rather than a direct secret comparison. Reject an `MCP_AUTH_TOKEN` equal to `CAPY_API_KEY`.
- [ ] Validate exact configured origins and bound POST-body reads before transport parsing. Accept authenticated non-browser clients with no Origin; no public browser origins by default. Close resources after a finite JSON response without relying on detached background work.
- [ ] Add `wrangler.jsonc` with compatibility date `2026-11-04`, necessary compatibility flags, generated binding types, logs and traces enabled, and invocation/payload logging disabled where supported. No real secrets in configuration.
- [ ] Run CLI build, child-process tests, Worker runtime tests, and `npx wrangler deploy --dry-run`; confirm generated validators run under workerd without dynamic evaluation. Commit the passing task.
