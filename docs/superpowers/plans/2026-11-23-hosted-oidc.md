# Hosted OIDC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Ship a self-hostable Workers MCP endpoint with configurable OIDC, encrypted per-user Capy keys, client consent/scopes, and effective revocation, preserving local STDIO.

**Architecture:** One Worker combines a browser account site, an OIDC relying party, and the supported single-Worker OAuth provider. D1 is authoritative for identities, encrypted credentials, browser sessions, login state and application grants; provider-managed OAuth grants/tokens use KV. Request-local MCP servers resolve only the authenticated account's current credential and enforce OAuth scopes before upstream work.

**Tech Stack:** Existing TypeScript/official MCP SDK 2.4.0, Vitest 4.1.12 and Cloudflare test plugin; Web Crypto; D1; KV; Workers rate-limit bindings. Pin published `@cloudflare/workers-oauth-provider` 1.3.0 and `openid-client` 6.9.1 after verifying installed types. Retain Node >=22 and existing working tools unless an actual incompatibility requires a recorded ruling. Current package types were inspected from a scratch npm tarball, not guessed from pre-1.x examples.

**Spec:** `docs/superpowers/specs/2026-11-23-hosted-oidc-design.md`, approved by Erin.

## Global Constraints

- One configured HTTPS OIDC issuer per deployment; identity is verified issuer + subject, never email. No policy means deny; when subject and signed-claim allowlists are both configured, both must match (AND).
- Use Authorization Code with S256 PKCE, browser-bound single-use state, and nonce. Enable `openid-client` non-repudiation checks explicitly: its normal token endpoint processing alone is not the required ID-token signature verification.
- Raw Capy keys belong only in HTTPS form submissions, encrypted D1 envelopes, and bounded request-local upstream headers. Never put them in OAuth props, client tokens, redirects, logs, screenshots, exceptions, or repository configuration.
- Encrypt with AES-256-GCM, fresh nonces, account/version-bound AAD, and a Worker-secret master key. One key per account; replace/delete invalidates old credential grants. New calls after revoke/disconnect must check authoritative primary D1 state, not cached credentials or OAuth KV propagation.
- Hosted mode removes shared `MCP_AUTH_TOKEN` and deployment-wide `CAPY_API_KEY` fallback. STDIO retains `CAPY_API_KEY` and optional groups and must not import hosted runtime dependencies.
- Keep the pinned 102 tools, six exclusions, deterministic schema generation, regex fixes, fixed Capy origin, deadlines/byte limits, and active-HTTP-abort propagation. No shared MCP session registry or cross-request cancellation routing.
- Use maintained OIDC/OAuth implementations and library consent helpers. Enforce application scopes at tool level, not by MCP's outer POST method.
- No project Setup changes, device/config changes, production data, real secrets in tests, package publication, or merge. Remote resources/deployment wait for an approved Cloudflare account, origin, registered OIDC app and secure secret provisioning.
- Work in this thread's isolated cloud feature checkout. Sequential writing subagents commit locally; the controller owns review, pushes, and PR lifecycle. Never push to a closed/merged PR.

## Review Focus

1. Same-email accounts, multiple issuers, malformed admission claims and changed policy must not select another user's credential (Tasks 1, 2, 4).
2. Concurrent credential replacement/revocation versus consent/token reuse must not grant stale or silently changed upstream authority (Tasks 1, 3, 4).
3. Callback replay, login/consent CSRF, forged return URLs and client metadata must not cross browser/client boundaries or leak secrets (Tasks 2–4).
4. Valid OAuth tokens with wrong resource, insufficient scope, stale grant state, or deleted credentials must fail before fetch even during concurrent calls (Task 4).
5. Missing rate-limit/storage/encryption bindings, provider outages, body floods and automatic observability must fail safely without exposing keys or disabling protections (Tasks 1–5).

## File Map and Shared Contracts

- `src/hosted/config.ts`: validated deployment configuration, admission rules, public route origins and limits.
- `src/hosted/store.ts`, `src/hosted/crypto.ts`, `migrations/0001_hosted_auth.sql`: D1 ownership/atomic persistence, envelope encryption and hashed opaque identifiers.
- `src/hosted/identity.ts`: trusted OIDC discovery/code exchange/claims validation and admission; `src/hosted/browser.ts`: browser sessions, login callbacks, CSRF and HTTP safeguards.
- `src/hosted/pages.ts`, `src/hosted/account.ts`: escaped server-rendered pages, own-key connect/delete/replace and own-grant management.
- `src/hosted/oauth.ts`: OAuth provider/options, server-side pending authorization and library-bound consent; `src/hosted/mcp.ts`: token context, authoritative credential lookup, stateless shared-server transport.
- `src/worker.ts`: composed hosted Worker entry point; `src/server.ts`: optional allowed-operation filter while keeping existing API compatible with STDIO.
- `tests/hosted/{store,identity,browser,account,oauth,mcp}.test.ts`, `tests/hosted/{fixtures,setup}.ts`: workerd integration with real local D1/KV and fake OIDC/Capy boundaries. `tests/hosted/config.test.ts` may run under Node for pure configuration checks.
- `wrangler.jsonc`, generated `worker-configuration.d.ts`, `vitest.workers.config.ts`, `tsconfig.workers.json`: all required bindings and hosted tests. `README.md`, `SECURITY.md`, `CONTRIBUTING.md`, CI: operator/client usage and validation.

Define shared records in `src/hosted/store.ts`: `Identity { issuer, subject, admissionClaims }`; `Account { id, identity, authorizationEpoch }`; `CredentialEnvelope { keyId, nonce, ciphertext, version }`; `AppGrant { id, accountId, providerGrantId, clientId, scopes, credentialVersion, authorizationEpoch, revokedAt }`; `BrowserSession { accountId, csrfHash, expiresAt }`; `LoginTransaction { stateHash, browserHash, verifier, nonce, continuation, expiresAt }`. All identifiers are opaque except the validated issuer/subject. SQL stores only the necessary signed admission attributes; display identity is optional and never authorization.

Expose `createStore(db: D1Database)` as one deep persistence module with named methods matching the operations below, using parameter binding and first-primary reads for authoritative authorization. New-request authorization is one joined current-account/current-credential/current-grant read. Do not persist plaintext Capy keys or depend on an in-memory process-wide map.

## Task 1: Configuration, encrypted vault, and authoritative persistence

**Files:** Create config/store/crypto modules, initial SQL migration and store/config tests; extend Worker bindings/test configuration/type coverage. Do not replace the existing Worker entry point yet. Existing single-principal tests stay runnable until Task 4 deliberately changes hosted auth.

**Interfaces:** `parseHostedConfig(env: Env): HostedConfig`; `admit(identity: Identity, config: HostedConfig): boolean`; `encryptCredential(key: string, accountId: string, version: number, config: EncryptionConfig): Promise<CredentialEnvelope>` and inverse `decryptCredential(...)`. Store methods: `getOrCreateAccount(identity)`, `getAccount(id)`, `putCredential(accountId, keyMaterialEnvelope, expectedVersion)`, `deleteCredential(accountId)`, `createGrant(record, expectedCredentialVersion, expectedEpoch)`, `getAuthorizedCredential(accountId, grantId, version, epoch)`, `listGrants(accountId)`, `revokeGrant(accountId, grantId)`, `disconnectAll(accountId)`, plus `createSession/getSession/deleteSession` and `createLogin/consumeLogin`. `consumeLogin` atomically deletes only an unexpired transaction matching both hashed state and browser binding. `putCredential` uses a version compare-and-swap; stale consent cannot insert a live grant after replacement.

- [ ] Implement modules and migration. ## Task 2: Generic OIDC sign-in and browser session security

**Files:** Create identity/browser modules and their tests; add pinned `openid-client`. Use Task 1 store/config rather than a second session store.

**Interfaces:** `beginLogin(request: Request, env: Env, continuation: InternalContinuation): Promise<Response>`; `finishLogin(request: Request, env: Env): Promise<Response>`; `requireSession(request, env): Promise<{ account, session } | Response>`; `requireMutation(request, env): Promise<{ account, session } | Response>`; `logout(request, env): Promise<Response>`. `InternalContinuation` is `{ kind: 'account' }` or `{ kind: 'authorize', transactionId: string }`, generated/validated on the server, never an arbitrary redirect URL.

- [ ] Write failing tests against a local fake issuer/JWKS/token endpoint for successful Google-style and tenant-specific Entra-style claims; signature/issuer/audience/azp/expiry/nonce/state mismatch; reused/missing browser-bound transaction; malicious return URL; same email/different subject; changed admission policy; disallowed scheme/host redirection; expired session and login CSRF. Observe RED.
- [ ] Implement Authorization Code/S256 with random state, nonce and verifier and explicit `enableNonRepudiationChecks`; require `expectedState`, `expectedNonce` and PKCE verifier at exchange. Validate issuer discovery and ID tokens with the installed library. Fetch only operator-configured HTTPS identity endpoints with bounded requests; tests inject fake issuer transport without exposing a runtime URL override. Persist no upstream identity access/refresh tokens. Callback consumes the D1 transaction atomically, applies admission, rotates session identity, and resumes only a stored internal continuation.
- [ ] Implement opaque `__Host-` session/login cookies (Secure, HttpOnly, SameSite=Lax, path `/`, no domain), one-hour absolute session lifetime and ten-minute login-state lifetime, strict logout/CSRF/origin checks, no-store responses, restrictive CSP/frame denial and escaped errors. CSRF secrets are browser-form values whose hashes live in session records. Public auth endpoints use the required limiter keyed by Cloudflare's trusted connecting IP where available, otherwise a restrictive shared anonymous bucket; never bypass for missing headers. Account mutation limits use authenticated account IDs.
- [ ] Run focused workerd tests to GREEN, both typechecks and current suite; commit. Tests use actual signed fake ID tokens so disabling signature verification makes them fail.
