# Hosted OAuth provider patch

The hosted Worker uses Cloudflare's MIT-licensed [Workers OAuth Provider](https://github.com/cloudflare/workers-oauth-provider) **1.3.0**. npm and the lockfile pin the published tarball. Its tarball integrity is `sha512-W0ENMmQ7LujqOKmvbMdYMI9bF+yC1KonfABZJbsK45fW/bjuGEwu3Uu52le9wIUFctm7d8x4emxzpLChQL9IXg==`. The generated copy applies these hosted corrections:

1. The CIMD origin request uses manual redirect handling and accepts exactly HTTP 200. Only then can the original host be shown as verified. The upstream public-fetch compatibility guard, validation, timeout, response byte limit and cache handling are unchanged.
2. For RFC 7009 refresh-token revocation, the provider checks the hash against the current/previous refresh token and matches the registered client to the grant. **After both checks**, it awaits the application's callback with only the verified user, provider grant ID, client ID and Worker bindings, **before** deleting the provider grant in KV. The callback revokes the matching D1 row. If the D1 write throws, the request fails without a successful acknowledgement; the provider hasn't yet deleted the credential used to retry. Access-token-only and unknown/unowned token handling is unchanged. The application does not infer these facts from token strings or HTTP status.
3. Provider console warnings use fixed text (and, in the default OAuth error hook, numeric status only). The library's direct CIMD failure/fallback, registration-renewal, and grant-cleanup warnings do not log client URLs, grant IDs, raw exceptions, or provider responses. This changes diagnostics, not OAuth wire responses or provider control flow.

`npm ci` runs the root `prepare` script. For an install that disables lifecycle scripts, run `npm run prepare` before using the Worker. The [generator](../scripts/prepare-oauth-provider.mjs) checks the upstream version and SHA-256 of both npm distribution files, requires each patch anchor exactly once, copies the MIT notice, and writes the patched runtime and declarations under the ignored `src/hosted/generated-provider/`. The Worker and workerd tests import that runtime, never an unpatched fallback. STDIO neither imports nor bundles it. Do not edit the generated files or just update the digest when an upstream check fails.

To review a dependency update, inspect the new tarball and upstream changes, recheck all patched code paths and new logging sites, remove patches fixed upstream, and update the verified inputs only after reviewing the remaining changes. Run `npm run prepare`, `npm run check:provider` (checks prepared files without changing them), `npm run typecheck`, `npm test`, and `npm run test:browser-consent` (local Chromium on PATH, or set `CHROMIUM_BIN`). The browser check uses an isolated local profile, in-memory D1/KV and test-only network boundaries; it exercises real form navigation without printing protocol credentials.
